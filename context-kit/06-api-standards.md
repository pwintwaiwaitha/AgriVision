# 06 - API Standards

## Base conventions

- Base path: `/api/v1`
- JSON request/response except image upload and file download.
- ISO 8601 UTC timestamps.
- Stable UUID identifiers.
- Explicit units in field names or unit fields.
- OpenAPI generated by FastAPI and treated as an acceptance artifact.
- Pydantic schemas for all public input and output.

## Authentication and authorization

- Use secure session or token authentication appropriate to the chosen deployment.
- Validate role and object permission in backend dependencies.
- Never trust a role, user ID, farm ID, or consent status sent by the client.
- Development demo mode may use seeded users, but production mode must refuse the
  demo-auth mechanism.

## Standard success envelope

```json
{
  "data": {},
  "meta": {
    "request_id": "uuid",
    "generated_at": "2026-09-02T00:00:00Z",
    "rule_or_model_version": "string",
    "data_status": "observed|user_provided|calculated|scenario|synthetic|missing"
  },
  "recommendation_context": {
    "summary": "",
    "assumptions": [],
    "risks": [],
    "safeguards": [],
    "confidence": "high|medium|low",
    "confidence_reason": "",
    "human_review_required": false,
    "human_review_reason": "",
    "next_safe_action": ""
  }
}
```

Omit `recommendation_context` for ordinary non-consequential CRUD responses.

## Standard error envelope

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "One or more fields need attention.",
    "field_errors": {
      "soil_moisture_pct": "Must be between 0 and 100."
    },
    "request_id": "uuid"
  }
}
```

Do not return stack traces, database messages, local paths, secrets, or internal model
details to clients.

## Required MVP endpoints

### Platform

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Liveness and basic version |
| GET | `/countries` | Supported country configuration |
| GET/PUT | `/me/adaptation-profile` | User adaptation and delivery mode |
| GET | `/me/consents` | Current consent states |
| POST | `/me/consents` | Grant a versioned, purpose-specific consent |
| DELETE | `/me/consents/{id}` | Withdraw optional consent |

### Track 1 - Sustain

| Method | Path | Purpose |
|---|---|---|
| POST | `/sustain/telemetry` | Process manual, simulated, REST or MQTT-normalized reading |
| POST | `/sustain/irrigation/recommend` | Run prototype irrigation support rule |
| POST | `/sustain/crop-screenings` | Upload and screen a crop image |
| POST | `/sustain/actions` | Record the action actually taken |
| POST | `/sustain/outcomes` | Record confirmed follow-up outcome |
| GET | `/sustain/workload-summary` | Estimated reclaimed hours with assumptions |

Compatibility aliases may preserve the implementation PDF paths:

- `POST /iot/telemetry`
- `POST /cv/diagnose`

Document aliases as deprecated if canonical routes are used.

### Track 2 - Attract

| Method | Path | Purpose |
|---|---|---|
| GET/PUT | `/attract/exploration-profile` | Youth interests, constraints and access pathway |
| GET | `/attract/pathways` | Filtered agriculture pathways |
| POST | `/attract/simulations` | Run five-year three-scenario digital twin |
| GET | `/attract/institutions` | Verified institutions/referrals |

Compatibility alias: `POST /simulator/run`.

### Track 3 - Bridge

| Method | Path | Purpose |
|---|---|---|
| GET/PUT | `/bridge/profile` | Mentor or learner matching profile |
| POST | `/bridge/matches/suggest` | Return up to three explainable suggestions |
| POST | `/bridge/matches/{id}/respond` | Accept or decline a suggestion |
| POST | `/bridge/matches/{id}/contact-release` | Release contact after all checks |

### Analytics and export

| Method | Path | Purpose |
|---|---|---|
| GET | `/analytics/charts/{chart_key}` | Approved chart data plus metadata |
| GET | `/analytics/metrics` | Filtered metrics with evidence status |
| POST | `/analytics/exports/sac` | Generate an audited SAC-ready export |

Compatibility alias: `GET /export/sac-data`.

## WebSockets

- `/ws/farms/{farm_id}/telemetry` may stream validated demonstration telemetry.
- Authorize the connection before upgrade and recheck farm access.
- Heartbeats and reconnect behaviour must be documented.
- Messages must include reading ID, timestamp, source and status.
- A WebSocket update is not permission to activate physical equipment.

## Validation examples

- `soil_moisture_pct`: 0-100 inclusive.
- `temp_c`: reject physically impossible configured values; warn on locally unusual
  values rather than hiding them.
- NPK values: non-negative with explicit unit.
- Image: JPEG/PNG, configured size limit, decoded safely.
- Coordinates: validate ranges and restrict precision in ordinary responses.
- Scenario years: exactly five for MVP output.
- Money: use decimal values and explicit ISO currency code.

## Pagination and filtering

List endpoints use `limit`, `cursor`, documented filters, deterministic order, and a
maximum page size. Do not expose unrestricted personal-data exports.

## Idempotency

Support idempotency keys for consent changes, contact release, action confirmation,
and export creation to prevent duplicate consequential records.
